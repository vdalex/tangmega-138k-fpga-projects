LiteX SoC on the hard AE350 with 1 GiB of DDR3 through Gowin's DDR3 Memory
Interface IP. Built with the Education edition; BIOS cross-built on aarch64.

    --with-gowin-ddr3
    --gowin-ddr3-netlist .../ddr3_memory_interface/ddr3_memory_interface.v
    --gowin-pll-init     .../src/pll_init.v

AHB2Wishbone never emitting a burst CTI, not the memory - see the README.

Control: litedram's GW5DDRPHY on pristine upstream master (278ecaf6a), no
patches of ours, the board's own target. Run to check whether the claim that it
"never converges" still held. It does not - it works at 1:2.

Note the failure is not diagnosed: with no window anywhere, calibration still
prints a "best" choice and proceeds to a memtest that fails on every word.

Also note 5.3 MiB/s against this project's 5.8 MiB/s before its L2 was added -
the same cause, add_sdram(..., l2_cache_size=0).

Building any of this needed one fix first: on current master the gowin_ae350
BIOS does not compile at all. The port's irq.h is empty while core.py now
reports CONFIG_CPU_HAS_INTERRUPT, so libbase's uart.c fails on implicit
declarations of irq_getie / irq_getmask / irq_setmask.
